# Telegram AI Bot

Telegram-бот на TypeScript: диалоги через OpenRouter, роли и пользовательские промпты, история общения, локальные и генерируемые фото, магазин пакетов, Telegram Stars и Platega, рефералы, промокоды, ежедневные бонусы, рассылки и административная панель.

## Требования и запуск

Нужны Node.js 22.13+ (ветка 22) либо 24+, npm, PostgreSQL 15+ и Redis 7+. Для запуска всего приложения достаточно Docker Compose:

```sh
cp .env.example .env
# Укажите реальные значения в .env.
docker compose up --build -d
docker compose logs -f bot
```

Внутри Compose используйте хосты `postgres` и `redis` в URL подключений. PostgreSQL хранит данные в volume `pgdata`. Миграции выполняются до запуска обработчиков и воркеров, в транзакции с advisory lock. Существующие таблицы и балансы сохраняются. `database_backup.sql` автоматически не импортируется.

Для разработки с отдельными локальными PostgreSQL и Redis замените хосты в `.env` на адреса этих сервисов и выполните:

```sh
npm ci
npm run dev
```

Для запуска скомпилированной версии переменные окружения должны быть экспортированы:

```sh
npm run build
node --env-file=.env --dns-result-order=ipv4first dist/main.js
```

## Конфигурация

Обязательные переменные: `BOT_TOKEN`, `ADMIN_ID`, `OPENROUTER_API_KEY`, `DATABASE_URL`, `REDIS_URL`. `ADMIN_ID` — положительный Telegram ID. Для Compose также задайте `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`. Для Platega нужны `PLATEGA_MERCHANT_ID` и `PLATEGA_SECRET`; без них этот способ оплаты недоступен.

Положите стартовые фотографии `.jpg`, `.jpeg`, `.png` или `.webp` в `src/assets/free_pics/` перед сборкой образа. Если фотографий нет, бот сообщит об этом и вернёт резерв фото. Модели и обращение к OpenRouter находятся в `src/infrastructure/ai/openrouter.ts`; шаблоны ролей — в `src/application/prompts.ts`.

## Архитектура

```text
src/
  main.ts                     # точка входа
  bootstrap/                  # сборка зависимостей, запуск и остановка
  config/                     # проверка окружения
  types/                      # типы по темам и контракты сервисов
  domain/                     # доменные правила и проверки
  application/                # сценарии AI, каталог, платежи, планировщик
  infrastructure/
    database/                 # репозитории по областям, транзакции, миграции
    ai/                       # OpenRouter и локальные фото
    payments/                 # HTTP-клиент Platega, проверка ответов API
    queues/                   # BullMQ, соединение Redis, воркеры
  presentation/telegram/      # middleware, доставка, меню и админка
migrations/                   # последовательные SQL-миграции
tests/                        # unit- и интеграционные тесты
```

Типы сгруппированы в `src/types/`: пользователи, диалоги, задания очередей, промокоды, покупки, сессии и контракты сервисов. Импортируйте их через `import type` из `@contracts/user`, `@contracts/purchases` и других тематических файлов. `@contracts/runtime` описывает зависимости приложения. Общих файлов с реэкспортом всех типов нет.

PostgreSQL-адаптеры разделены на `users`, `balances`, `conversations`, `settings`, `promotions`, `campaigns` и `administration`; `repository.ts` объединяет их для существующих сценариев. Магазин разделён на `menu`, `stars`, `platega` и `polling` в `@shop/*`. `bootstrap` отвечает за создание зависимостей и корректную остановку; просроченные сессии очищаются отдельным прикладным сервисом. Сборка очищает `dist`, чтобы удалённые модули не оставались в артефактах.

Домен и прикладные сценарии не импортируют Telegram, PostgreSQL или SDK OpenAI. Зависимости передаются при создании сервисов. Импорт модулей не запускает подключения, таймеры или бота. `strict`, `noUncheckedIndexedAccess` и `exactOptionalPropertyTypes` включены; ESLint запрещает `any` и подавление ошибок TypeScript.

## Импорты

Для связей между модулями используйте алиасы; для соседних файлов оставляйте короткие `./file.js`:

```ts
import { loadConfig } from '@config/env';
import type { User } from '@contracts/user';
import { createAiService } from '@app/ai';
import { createRepository } from '@database/repository';
import { registerCore } from '@telegram/core';
```

Короткие алиасы объявлены в `tsconfig.json`:

| Алиас | Каталог |
| --- | --- |
| `@bootstrap/*` | `src/bootstrap/*` |
| `@contracts/*` | `src/types/*` |
| `@shop/*` | `src/presentation/telegram/shop/*` |
| `@config/*` | `src/config/*` |
| `@domain/*` | `src/domain/*` |
| `@app/*` | `src/application/*` |
| `@database/*` | `src/infrastructure/database/*` |
| `@providers/*` | `src/infrastructure/ai/*` |
| `@payments/*` | `src/infrastructure/payments/*` |
| `@queues/*` | `src/infrastructure/queues/*` |
| `@telegram/*` | `src/presentation/telegram/*` |
| `@admin/*` | `src/presentation/telegram/admin/*` |
| `@handlers/*` | `src/presentation/telegram/handlers/*` |

Используйте ближайший алиас модуля: `@admin/users`, а не `@telegram/admin/users`. В разработке и тестах алиасы разрешает `tsx`; `npm run build` преобразует их в относительные ESM-пути с расширением `.js` через `tsc-alias`. Поэтому `npm start` и Docker работают на обычном Node.js без дополнительного загрузчика. ESLint проверяет границы архитектуры и для алиасов.

## Проверки

`tsconfig.json` включает исходники и тесты и явно подключает типы Node.js (`types: ["node"]`), поэтому редактор проверяет `node:crypto`, `node:test` и остальные встроенные модули в том же проекте. `tsconfig.build.json` собирает только `src/`; тесты в production-образ не попадают.

```sh
npm run check                 # форматирование, типы, ESLint, тесты, сборка
npm run format                # Prettier и автоматическая сортировка импортов
npm run format:check          # проверка форматирования и порядка импортов
```

Prettier использует `@ianvs/prettier-plugin-sort-imports`: сначала идут встроенные модули Node.js, затем внешние пакеты, затем внутренние алиасы, затем относительные импорты (родительские перед соседними). Группы разделены пустой строкой; импорты из одного модуля объединяются, именованные импорты сортируются автоматически. Настройки находятся в `.prettierrc.json`.

Интеграционные тесты включаются отдельно:

```sh
TEST_DATABASE_URL=postgres://postgres:test@localhost:5432/bot_test \
TEST_REDIS_URL=redis://localhost:6379/15 npm test
```

Используйте выделенные тестовые сервисы. PostgreSQL-тесты создают и удаляют собственную схему. Redis-тесты очищают очередь `ai-requests` в указанной базе; не подключайте их к рабочему Redis. Без этих переменных интеграционные группы пропускаются.

## Поведение и эксплуатация

- `/start`, `/buy`, `/admin` и существующие пользовательские меню сохранены. Все семейства административных callback-команд проходят общую проверку прав.
- Начальный баланс: 10 сообщений и 1 фото. Реферал даёт пригласившему 10 сообщений, новому пользователю — ещё 5. Ежедневный бонус составляет 1–3 сообщения и выдаётся раз в 24 часа; можно включить проверку подписки на канал.
- Пакеты, цены, справочные тексты, ссылки и настройки бонусного канала редактируются в админке. Выдача VIP сохраняет существующее поведение: пакет 9999 сообщений и 9999 фото. Генерация голосовых сообщений не реализована.
- Покупка сохраняет цену, скидку, валюту и состав пакета при создании счёта. Подтверждение проверяет владельца и реквизиты, а зачисление выполняется транзакционно и однократно. Platega проверяется фоновым опросом; незавершённые счета восстанавливаются из БД после перезапуска.
- Счета старой JavaScript-версии не содержат сохранённого снимка покупки и автоматически не зачисляются новой версией. Перед переключением завершите старые счета либо сверяйте их вручную через поддержку.
- Сообщения резервируются атомарно воркером; при ошибке генерации резерв возвращается. BullMQ может повторно обработать задачу после аварийного завершения процесса: внешняя генерация не имеет гарантии exactly-once.
- Дневные расходы AI сбрасываются по дате PostgreSQL. Лимит стоимости изображений проверяется перед запросом и зависит от стоимости, которую возвращает провайдер; это не жёсткая квота провайдера.
- Черновики административного ввода и локальные ограничения частоты находятся в памяти процесса. Для нескольких экземпляров потребуется общее хранилище сессий. На `SIGINT`/`SIGTERM` приложение останавливает таймеры, ожидает фоновые задачи, закрывает воркеры, очереди и пул БД.

Не коммитьте `.env`, платёжные ключи и персональные данные. Docker-контекст исключает `.env` и SQL-дамп; runtime-образ содержит собранное приложение и работает от пользователя `node`.
