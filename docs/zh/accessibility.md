# 无障碍

[English](../eng/accessibility.md) · [Русский](../ru/accessibility.md) · **简体中文**

## 范围

项目界面由 Telegram 消息、内联按钮和回复键盘组成。显示、缩放、键盘导航及辅助技术交互依赖具体客户端和设备。仓库没有独立网页界面。

本文描述当前行为及界面变更的检查项。尚未公布人工屏幕阅读器测试结果或正式标准符合性评估。

## 当前行为

- 主要操作有文字标签，包括个人资料、商店、帮助、AI 设置和管理菜单。
- 余额、价格和操作结果通过文字表达，不仅依赖图片。
- 长度限制、等待时间和余额不足都有说明。
- AI 文字按最多 4096 字符拆分，图片带文字说明。
- 群发在确认前提供预览。

表情符号用于菜单、资料和状态。一些紧凑按钮只有表情和数字，需结合完整菜单检查其含义是否清楚。

## 限制

- 服务文字主要为俄语，没有通用界面本地化机制。
- 某些操作编辑已有消息，需在具体客户端中检查重新朗读和焦点位置。
- 图片没有保证包含内容描述的独立字段，AI 说明不一定是有效替代文本。
- 尚未实现语音响应或单独音频模式。
- 没有专门的无障碍验证器检查 AI 生成文本。
- 固定冷却时间要求用户等待，没有独立的交互速度设置。

## 菜单变更的人工检查

提交界面变更前检查：

1. 是否能到达 `/start`、资料、帮助、商店，并从子菜单返回。
2. 测试设备上的屏幕阅读器能否读取标签和操作结果。
3. 不只依赖表情、颜色或位置时，含义是否仍然明确。
4. 支持键盘操作的 Telegram 客户端中的导航。
5. 长名称、大数值、错误信息和图片说明。
6. 编辑消息、取消输入和切换角色后的上下文。

标签使用简短动作，错误提供明确说明，为有意义的图片提供说明。类型和处理器测试之外，还需要人工检查实际客户端。

## 报告问题

通过 [Issue](https://github.com/Hostlife22/ai-bot-with-payments/issues) 描述受影响菜单或操作、Telegram 客户端、操作系统、导航方式、预期和实际行为；必要时注明屏幕阅读器及版本。可附清理后的截图或录屏。

无需提供医疗信息、凭据、支付信息或真实对话。如果同时涉及漏洞或他人数据泄露，请采用[安全报告](security.md)中的私密流程。
