## 用户命令与菜单

| 操作                          | 行为                                           |
| ----------------------------- | ---------------------------------------------- |
| `/start`                      | 注册、推荐处理和条款确认。                     |
| `/buy` 或个人资料中的商店按钮 | 选择套餐和支付方式。                           |
| 个人资料                      | 查看余额和进度，领取奖励或输入优惠码。         |
| AI 设置                       | 选择角色，或设置最多 1000 字符的自定义提示词。 |
| 清除上下文                    | 删除用户的 `messages` 历史。                   |
| 推荐                          | 显示 `https://t.me/<bot>?start=ref_<ID>`。     |
| 帮助                          | FAQ、支持、协议和隐私政策。                    |

当前服务界面主要使用俄语。切换角色会清空历史。没有选择提示词时，`application/ai.ts` 从 `flirt` 开始，历史达到至少六条消息后固定为 `flirthot`。

传入图片、视频、文档和动画用于管理员准备群发。模型不会分析普通用户的媒体文件，也不会生成语音。

## 管理员权限

在 `ADMIN_ID` 中设置数字 Telegram ID，再执行 `/admin`。权限按 ID 而非用户名检查。管理员跳过条款确认、5 秒用户冷却和普通请求长度限制；AI 服务独立的每分钟窗口 10 次请求限制仍然适用。

统计显示用户、分币种收入和漏斗。部分指标是近似值：免费使用通过当前余额 `< 10` 推算，并非事件账本。文字费用使用平台返回值或适配器系数；图片费用仅在平台返回时记录。

## 用户与余额

按 ID 或列表查找用户，可封禁、替换余额、赠送套餐、查看支付记录或发送管理消息。

编辑余额是替换数值，赠送套餐是增加资源。VIP 增加 9999 条消息和 9999 张图片，不创建订阅期限。手动赠送套餐还会设置 `has_purchased` 并清除折扣。

全局重置会把所有用户余额替换为 10 条消息和 1 张图片，包括付费余额。仅在确实需要整体替换时使用。Free Mode 单独关闭文字余额检查和扣减，但保留图片限制。

## 价格、文本和频道

套餐编辑接受四个非负整数：

```text
Stars RUB 消息数 图片数
65 80 50 5
```

两种价格必须为正，至少包含一种资源。已开具账单保留原快照。

内容设置管理政策、协议、FAQ 和链接。政策与协议使用 HTML；FAQ 会转义，所以 HTML 标签显示为文字。管理消息使用 HTML，群发使用 Telegram Markdown。由于格式不同，请检查预览。

`bonus_channel_id` 接受 `@username` 或数字频道 ID，`bonus_channel_url` 是跳转链接。将机器人设为频道管理员，并用普通用户验证。订阅检查出错时不会发放奖励。

## 奖励与优惠码

初始余额为 10 条消息和 1 张图片。首次通过其他有效用户的链接注册时，推荐者获得 10 条消息，新用户额外获得 5 条。已注册用户重复 `/start` 不会再次获奖。

每日奖励为 1–3 条消息，每个滚动 24 小时可领取一次，可要求先通过频道订阅检查。条件 SQL 更新防止并发重复领取。

创建优惠码草稿，设置资源、折扣和次数后保存。未保存草稿在内存中。用户输入会转为大写，新建代码中的空格替换为 `_`。

激活检查有效状态、全局剩余次数、用户使用次数及首次购买条件。折扣为 0–100。“新用户”指 `has_purchased` 为假，而非最近注册。

## 群发与提醒

发送文本或媒体，选择按钮，查看预览并确认。任务入队不等于所有用户已收到；发送错误会记录，群发处理器不会自动重试。

每 5 分钟执行：

- 最近一次普通文字活动在 24–48 小时前且未被标记的用户收到提醒。
- 两小时前打开商店但未购买的用户收到一次性代码，提供 20% 折扣和 5 条消息。
- 每日奖励可领取且尚未标记通知的用户收到提醒。

这些活动没有统一的管理开关。标记保存在数据库中，不会每次访问自动重置。购物车代码含接收者 ID，但激活时不检查所有者或有效期，因此并未在技术上限制为该账户专用。
