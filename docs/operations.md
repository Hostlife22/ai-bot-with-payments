# Эксплуатация

[К документации](../README.md#документация)

## Запуск, проверка и обновление

```sh
docker compose up --build -d
docker compose ps
docker compose logs --tail=100 bot
```

Healthcheck настроен для PostgreSQL и Redis. Собственного HTTP health endpoint у бота нет. После запуска проверьте `/start`, профиль и `/admin` с разрешённого ID; успешная сборка не проверяет реальные ключи внешних сервисов.

Перед обновлением сохраните резервную копию БД, `.env` отдельно от репозитория и используемые фотографии. Для обновления только приложения:

```sh
docker compose up --build -d bot
```

Миграции выполняются при старте. Автоматического отката схемы нет; возврат старого образа безопасен только при совместимости со схемой. Не запускайте одновременно старую и новую polling-версию с одним токеном.

Compose не задаёт `stop_grace_period`, а AI-запрос может выполняться до 120 секунд. Для штатной остановки оставьте время на завершение работы:

```sh
docker compose stop -t 180 bot
```

Это время ожидания, а не гарантия завершения всех внешних запросов. Принудительное завершение может оставить резерв баланса и незавершённую задачу.

## Хранение данных

- PostgreSQL использует именованный том `pgdata`. Обычный `docker compose down` его сохраняет; флаг `-v` удаляет том.
- Для Redis в Compose не заданы именованный том и отдельная политика сохранения очередей. Не рассчитывайте на сохранение всех заданий при пересоздании сервиса.
- Снимки покупок хранятся в PostgreSQL; проверка подходящих счетов Platega возобновляется после запуска независимо от AI-очереди.
- Черновики, выбранный администратором пользователь и ограничения частоты находятся в памяти. Перезапуск их сбрасывает.
- История диалогов не имеет автоматического срока хранения; очистка контекста удаляет её для конкретного пользователя.

Для нескольких экземпляров нужны отдельное решение для получения Telegram updates, общее хранилище сессий и координация фоновых напоминаний. Только блокировка SQL-миграций этого не обеспечивает.

## Резервная копия PostgreSQL

Пример создаёт custom-format дамп вне репозитория:

```sh
mkdir -p ../ai-bot-backups

docker compose exec -T postgres sh -c \
  'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" --format=custom' \
  > "../ai-bot-backups/bot-$(date +%Y%m%d-%H%M%S).dump"
```

Проверьте код завершения команды и содержимое дампа через `pg_restore --list`. Дамп содержит пользовательские данные и историю платежей; храните его отдельно от исходников.

Проверяйте восстановление в новой БД. Замените имя файла в примере:

```sh
docker compose exec -T postgres sh -c \
  'createdb -U "$POSTGRES_USER" bot_restore'

docker compose exec -T postgres sh -c \
  'pg_restore -U "$POSTGRES_USER" -d bot_restore --no-owner --no-privileges' \
  < ../ai-bot-backups/backup.dump
```

Эти команды не переключают приложение на восстановленную БД. Для переключения сначала остановите бот, согласуйте `DATABASE_URL`, выполните запуск и проверьте балансы, платежи и историю миграций. `database_backup.sql` в репозитории автоматически не используется.

## Миграции

Файлы перечислены явно в [migrate.ts](../src/infrastructure/database/migrate.ts). `init.sql` выполняется идемпотентно, затем исполняются ещё не записанные в `schema_migrations` миграции. Весь проход защищён транзакцией и advisory lock.

Для диагностики можно открыть `psql`:

```sh
docker compose exec postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
```

Примеры запросов только для чтения:

```sql
SELECT name, applied_at FROM schema_migrations ORDER BY name;
SELECT id, provider, amount, currency, provider_tx_id, fulfilled_at, canceled_at
FROM purchase_intents ORDER BY created_at DESC LIMIT 20;
```

Не публикуйте результаты с идентификаторами пользователей и транзакций в открытом доступе.

## Диагностика

| Симптом | Что проверить |
| --- | --- |
| `Missing required environment variable` | Наличие обязательного поля и способ передачи `.env`; `npm start` файл сам не читает. |
| Ошибка Node.js types в тестах | `npm ci`, основной `tsconfig.json`, workspace TypeScript и перезапуск TS Server. |
| PostgreSQL недоступен | Готовность сервиса, URL, пароль уже созданного пользователя; имена контейнеров и адреса хоста различаются. |
| Задачи не выполняются | `REDIS_URL`, выбранную Redis БД, логи очереди и воркера. |
| Бот конфликтует при polling | Другой процесс или окружение с тем же токеном. |
| Бесплатные фото недоступны | Каталог внутри runtime-образа, расширения файлов и пересборку после добавления фото. |
| Нет генерации изображений | Балансы текста/фото, `has_purchased`, дневные расходы, доступность модели и формат ответа OpenRouter. |
| Не выдаётся бонус канала | ID канала, права бота и фактическую подписку пользователя. |
| Platega недоступна | Оба ключа, HTTP-ошибки, возврат провайдером допустимых JSON и HTTPS-ссылки. |
| Оплата не зачислена | UUID покупки, сумму, валюту, payload, привязанную транзакцию и состояние в `purchase_intents`. |
| Рассылка завершилась частично | Ошибки доставки, блокировки бота пользователями и разметку сообщения. |

При сверке платежа сначала сопоставьте ответ провайдера с сохранённой покупкой. Не снимайте уникальность `payments.tx_id` и не обнуляйте `fulfilled_at` ради повторного начисления. История и ручная выдача доступны в админке.

## Учёт расходов и известные пределы

Дневная сумма расходов сбрасывается логически при смене даты PostgreSQL. Порог изображений проверяется перед запросом при значении не менее 1 USD. Это проверка учтённых затрат, а не резерв бюджета: параллельные генерации могут пройти её одновременно, а отсутствие стоимости в ответе провайдера оставит расход изображения неучтённым.

Оценка стоимости текста при отсутствии `usage.cost` использует коэффициенты в адаптере. При смене модели отдельно проверьте расчёт; отображаемая статистика не заменяет данные провайдера.
